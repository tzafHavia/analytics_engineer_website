## 3. Risks & technical watch-items

- **K1 — Serverless DB connection exhaustion → ✅ RESOLVED 2026-06-27.** Both pools
  (`dashboardData.js`, `pgClient.js`) now share one config: `max` from `DB_POOL_MAX` (default
  3, clamped ≥1), finite `connectionTimeoutMillis: 10000`, `idleTimeoutMillis: 10000`, ssl.
  Verified: `max=3` and `max=1` both return identical real data with no acquire-timeout
  (warm run ~5s). **At deploy: set `DB_POOL_MAX` in Vercel** (recommend 3; 1 = max-safety,
  slower renders). See `POOL_TUNING_PLAN.md`.
- **K2 — SuiteCRM unreachable in prod (HIGH).** See D1. Without a decision the contact form
  partially breaks in prod.
- **K3 — Agent session quota (MEDIUM).** Last session the subagents returned 0-token
  session-limit errors and the orchestrator coded directly. Confirm quota before delegating
  R2/R3, or expect direct implementation.
- **K4 — Stale WhatsApp/CRM tokens (MEDIUM).** Dev tokens can expire; validate in prod (D3).
- **K5 — Data-design caveat (carry into R2).** `OUT_OF_STOCK` is dominant because on-hand qty
  comes from a single-row source; `STOCKOUT_RISK` is the genuinely dynamic signal.
- **K6 — Enum casing / `item_id` TEXT / Turbopack `@keyframes`** — standing constraints
  (CLAUDE.md), relevant to R2 and R3.
